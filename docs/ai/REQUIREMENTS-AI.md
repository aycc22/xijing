## 1. 文档目的

本文档定义习径接入 DeepSeek 大模型后的**增量产品范围**：题目/考点辅助分析、刷题或考试结束后的智能薄弱点分析、**学习者揭晓后的单题 AI 点评**、考试主观简答（`short_answer`）的 AI 辅助评分。

本文档是产品设计、技术设计（见 [DESIGN-AI.md](./DESIGN-AI.md)）、研发拆解、测试与上线验收的共同依据。它是主需求说明书 [REQUIREMENTS.md](../../REQUIREMENTS.md) 的**增量模块**，不替代主需求书；冲突时以本文档对 AI 模块的专门约定为准，其余仍服从主需求书。

需求优先级：

- **P0**：本模块首个可上线切片必须具备。
- **P1**：重要增强，建议在完整 AI 能力版本内具备。本修订将 P1 拆为 **P1a**（学习者揭晓后点评，先做）与 **P1b**（上传者打标写回）。
- **P2**：可后置，不阻塞 P0/P1 上线。

## 2. 背景与可行性结论

### 2.1 背景

习径已具备题库、刷题、考试、错题本与结果回顾。主需求 §12.2 要求按知识点统计正确率与薄弱知识点，但产品侧尚未消费 `questions.tags`；考试 `short_answer` 目前仅靠字符串模糊匹配，语义评分能力不足。用户希望引入 DeepSeek，对题目考点、单次刷题/考试表现、**揭晓后单题讲解**以及主观简答进行智能分析与辅助评分。

### 2.2 可行性结论

**可行。** 技术栈为 Vue 3 SPA + Supabase（Auth / Postgres / RLS / Edge Functions），已有 `email-auth` 代理外部服务的模式，可将 DeepSeek API Key 置于服务端 Secrets，由 Edge Function 统一代理调用。各能力均可实现，难度与产品契合度不同：

| 能力 | 可行性 | 说明 |
|------|--------|------|
| 题目 / 考点分析 | 高 | 复用 `questions.tags`，补生成与编辑流水线 |
| 会后智能薄弱点分析 | 高 | 会话答案与错题数据齐备；可先本地聚合再 AI 叙述 |
| 揭晓后单题 AI 点评 | 高 | 复用 `ai-proxy` 与分析配额；按题目缓存教学正文 |
| 主观简答 AI 评分 | 中 | 需异步阅卷、采分点 Prompt、明确「仅供参考」边界 |

主需求 §2.4 与 CONTEXT 曾将「AI 自动评分」等列为首期不包含；本模块启动后，相关条目改为指向 `docs/ai/`（见主文档修订说明），本模块按下文分期交付，**不**一次做完全部 AI 畅想功能。

### 2.3 已锁定前提

1. **客观案例小题**（`case_id` + `single` / `multiple` / `judgement`）：继续选项键精确判分，**禁止**用 AI 改写对错或得分。
2. 「案例题用 AI 评分」在本产品中落地为：考试模式 **`short_answer` 主观简答**（可附带案例材料）的语义辅助评分。
3. **考点**首期复用 `questions.tags: string[]`，不新建独立考点 taxonomy 表。
4. 所有 DeepSeek 调用经 Supabase Edge Function；密钥不得进入前端 `VITE_*`。
5. 实现分期：**P0 题库手改 tags + 会后薄弱点分析 → P1a 学习者揭晓后单题点评 → P1b 题目考点 AI 打标 → P2 简答异步 AI 评分**。
6. 主观简答得分双轨：正式 `earned`/总分不由 AI 覆盖（见 [ADR-0001](../adr/0001-ai-short-answer-dual-score.md)）。
7. AI 日配额仅在**成功调用 DeepSeek 并得到可用结果**后递增；失败/降级不计次。
8. 「已手改/已确认 tags」用 `questions.tags_edited_at` 判定（手改保存与 AI 确认写入均更新该戳）。
9. 试卷 JSON 导入须写入源数据中的 tags（有则写入，无则 `[]`），纳入 P0。
10. P0 在智能分析区固定披露：题干/解析/作答可能发送至 DeepSeek。
11. 学习者「AI 点评」**仅揭晓后**可用；覆盖全部可作答题型；**不得**改写客观分 / `is_correct` / `earned`；点评返回的建议 tags **默认不写回**题目（写回仍走 P1b `analyze_question`）。

## 3. 术语

| 术语 | 含义 |
|------|------|
| **客观案例题** | 共享 `case_id` / `case_material` 的客观小题组，小题题型为单选/多选/判断 |
| **主观简答** | `qtype = short_answer`，用户输入文本；当前仅考试模式有作答 UI |
| **考点** | 首期等同题目 `tags` 中的知识点标签字符串 |
| **会话 AI 报告** | 一次已完成刷题或考试会话对应的薄弱点汇总与自然语言解读 |
| **AI 点评 / AI-EXPLAIN** | 揭晓后对**单题**生成的教学向解读（考点、考查意图、易混点、点评）；入口文案为「AI 点评」 |
| **揭晓** | 刷题：该题已提交或「暂不会」，从而展示正误与解析；考试：整卷已交卷且该题出现在结果明细中 |
| **AI 辅助评分** | 对主观简答给出建议得分、评语与采分点命中说明；**不具备官方阅卷效力** |
| **本地考点聚合** | 不调用大模型，仅按 tags 统计当次正确率 / 错题分布 |
| **DeepSeek 代理** | Edge Function `ai-proxy`，按 `action` 分发分析、点评与评分请求 |

## 4. 目标与非目标

### 4.1 目标

- 帮助上传者快速为题目补全或建议考点标签，提升后续薄弱点分析质量。
- 在学习者完成一次刷题或考试后，给出可理解的薄弱点解读与复习建议。
- 在学习者**单题揭晓后**（刷题过程中或结果/复盘）讲解考点、考查意图与易混点，可一句关联本题对错。
- 对考试主观简答提供基于参考答案与采分点的 AI 辅助评分与反馈。
- 在成本、隐私与权限可控的前提下接入 DeepSeek。

### 4.2 非目标

- AI 自动出题、自动生成整套试卷。
- 在线监考、防作弊、人脸识别。
- 用 AI 替代客观题（含客观案例小题）的精确判分，或改写 `is_correct` / `earned` / 会话总分。
- 将 AI 评分结果等同于正式考试官方成绩或人工阅卷终审。
- 未登录用户调用 AI。
- **揭晓前**的答案提示、解析剧透或辅导（含考试交卷前）。
- 自由对话式聊天助教、多轮追问；点评是一次结构化生成，不是通用 tutor chat。
- 练习模式（刷题）扩展主观简答作答 UI（P2 明确不做；若未来需要另立需求。简答仅在**已展示作答/复盘的入口**提供点评）。
- 独立商业化计费、按次向终端用户收费（首期仅平台侧配额控制）。
- 学习者点评路径把建议 tags 写回题库（与 P1b 上传者打标分离）。

## 5. 角色与权限

| 能力 | Learner | Uploader | Admin |
|------|---------|----------|-------|
| 对自己的已完成会话触发 / 查看 AI 报告 | 是 | 是 | 是 |
| 查看他人会话 AI 报告 | 否 | 否 | 否（除非后续另定运维权限；首期不做） |
| 对可练习题目在揭晓后触发「AI 点评」 | 是 | 是（练习/复盘时与 learner 相同） | 是（练习/复盘时与 learner 相同） |
| 将点评返回的建议 tags 写回题目 | 否 | 否（须走 AI-TAG 预览确认） | 否（须走 AI-TAG） |
| 人工编辑题目 tags（不经 AI） | 否 | 仅自己题库 | 全部题库 |
| 对题目触发 AI 考点分析并写回 tags | 否 | 仅自己题库 | 全部题库 |
| 人工编辑 / 覆盖 AI 建议的 tags | 否 | 仅自己题库 | 全部题库 |
| 触发主观简答 AI 评分（本人试卷） | 是（交卷流程内） | 是 | 是 |
| 配置平台 DeepSeek 密钥与总开关 | 否 | 否 | 运维侧（Supabase Secrets / 部署配置，非产品内 UI） |

权限规则：

- **AI-AUTH-01 P0**：所有 AI 接口必须携带有效登录 JWT；未登录返回 401。
- **AI-AUTH-02 P0**：会话分析与评分仅允许会话 `user_id` 等于当前用户。
- **AI-AUTH-03 P1b**：题目打标仅允许题库 owner（uploader）或 admin。
- **AI-AUTH-04 P0**：前端不得持有 DeepSeek API Key。
- **AI-AUTH-05 P1a**：`explain_question` 须登录；题目须对当前用户可见（已发布题库，或未发布题库的 owner/admin）。**有会话时**须校验会话归属且该题已揭晓。uploader/admin **不得**因角色绕过揭晓（题库管理打标走 `analyze_question`，不走点评入口）。

## 6. 功能需求

### 6.0 AI-TAG-EDIT — 题库手改考点（P0 前置）

- **AI-TAG-EDIT-01 P0**：上传者/管理员在题库管理中可对单题**手工编辑** `tags`（增删改字符串列表）并保存，不调用 DeepSeek；保存成功须更新 `questions.tags_edited_at`。
- **AI-TAG-EDIT-02 P0**：保存后的 tags 立即参与后续会后分析的本地考点聚合（联表 `questions`）。
- **AI-TAG-EDIT-03 P0**：本能力是会后分析可验收的前提；无手改入口则不得将「考点聚合」标为完成。
- **AI-TAG-EDIT-04 P0**：试卷 JSON 导入写入题目时，若源数据含 tags 则写入 `questions.tags`，否则 `[]`（修正既有写死空数组行为）。
- **AI-TAG-EDIT-05 P0**：CSV 导入若写入非空 tags，亦更新 `tags_edited_at`（视为上传者提供的标签）；空 tags 不打戳。

### 6.1 AI-SESSION — 会后智能薄弱点分析（P0）

- **AI-SESSION-01 P0**：用户完成刷题会话（`attempt_sessions.finished_at` 非空）后，在结果页可查看或触发「智能分析」。
- **AI-SESSION-02 P0**：用户完成考试会话（已调用 `finish_exam_session`）后，在考试结果页可查看或触发「智能分析」。
- **AI-SESSION-03 P0**：系统先做**本地考点聚合**：按题目 `tags` 统计当次作答的正确数、错误数、正确率；无 tag 的题目归入「未标注」。
- **AI-SESSION-04 P0**：薄弱考点展示遵循主需求 §12.2 精神：当次会话内某考点作答量达到最低样本数后再标为「薄弱」候选；**当次会话默认阈值 ≥ 1 即可列出错题相关考点**，跨会话累计薄弱统计若后续接入个人统计页，默认仍 ≥ 5。本模块 P0 以**当次会话**为主，阈值配置默认：当次列出错误相关考点不设 5 题门槛；AI 叙述中可提示「样本较少，仅供参考」。
- **AI-SESSION-05 P0**：在本地聚合结果之上，调用 DeepSeek 生成：`summary`（一段总结）、`weak_points[]`（薄弱点列表）、`suggestions[]`（复习建议）。
- **AI-SESSION-06 P0**：同一会话重复请求：若已存在成功报告，默认直接返回已存报告（幂等）；提供「重新生成」需消耗配额并覆盖。
- **AI-SESSION-07 P0**：DeepSeek 不可用或超限时，结果页仍展示本地考点聚合，并提示「智能解读暂不可用」。
- **AI-SESSION-08 P0**：报告仅会话所有者可读；落库后受 RLS 保护。
- **AI-SESSION-09 P1**：支持从结果页一键跳转错题本或按薄弱考点筛选练习（若筛选能力尚未具备，可先跳转错题本）。

### 6.2 AI-EXPLAIN — 学习者单题点评（揭晓后）（P1a）

本切片排在当前已上线 P0（会后分析）之后、上传者 AI 打标（P1b）之前：学习者可立即消费教学向点评，且**不依赖** tags 写回。

- **AI-EXPLAIN-01 P1a**：全部可作答题型均可点评：客观 `single` / `multiple` / `judgement`、案例材料下的关联客观小题，以及界面**已展示**的 `short_answer`（当前练习模式无简答作答 UI 时，仅考试交卷后复盘等已揭晓入口提供）。
- **AI-EXPLAIN-02 P1a**：入口按钮文案为 **「AI 点评」**。刷题过程中（[`QuizView.vue`](../../src/views/QuizView.vue)）仅在该题**揭晓后**展示；提交 / 「暂不会」之前不得出现或可点。
- **AI-EXPLAIN-03 P1a**：已完成练习结果页与考试交卷后结果页的逐题复盘播放器（[`SessionReviewPlayer.vue`](../../src/components/SessionReviewPlayer.vue)）提供同一入口（题目已揭晓）。考试作答过程中（交卷前，[`ExamView.vue`](../../src/views/ExamView.vue)）不得出现。题库发布前预览（不展示答案）不得出现。
- **AI-EXPLAIN-04 P1a**：目的是讲解知识点 / 考点 / 考查意图 / 易混点；可简要关联用户本题对错或跳过。**禁止**改写 `is_correct`、`earned`、会话总分或任何客观判分结果。
- **AI-EXPLAIN-05 P1a**：与 P0 会后报告（`analyze_session`）区分：点评是**单题教学**，会后报告是**当次会话薄弱点汇总**；二者独立，互不替代、互不阻塞。
- **AI-EXPLAIN-06 P1a**：与 P1b `analyze_question` 区分：点评面向学习者，返回教学正文；`related_tags` **仅展示、默认不写回** `questions.tags` / 不更新 `tags_edited_at`。考点写回仍仅由上传者/管理员在题库管理中经 AI-TAG 预览确认完成。
- **AI-EXPLAIN-07 P1a**：同一题目内容未变更时，优先返回缓存点评，不重复计费；提供「重新生成」须消耗配额并覆盖该题缓存。
- **AI-EXPLAIN-08 P1a**：DeepSeek 不可用或超限时，页面保持原解析与对错展示，并提示点评暂不可用；不得阻断刷题 / 复盘主路径。
- **AI-EXPLAIN-09 P1a**：须登录。无会话或本题尚未揭晓 → 明确错误（如 `not_ready`）；无权见题或非本人会话 → 403。
- **AI-EXPLAIN-10 P1a**：点评面板固定披露：题干 / 选项 / 解析 / 参考答案可能发送至 DeepSeek；口径对齐 P0 智能分析区脚注。不把用户作答作为共享缓存的一部分（见设计文档）。

### 6.3 AI-TAG — 题目 / 考点分析（P1b）

- **AI-TAG-01 P1b**：上传者/管理员在题库管理中可对**单题**触发「AI 分析考点」。
- **AI-TAG-02 P1b**：支持对题库内题目**批量**触发（需进度与失败列表）；单次批量上限由技术文档规定（默认 ≤ 50）。
- **AI-TAG-03 P1b**：输入至少包含题干；宜包含选项、解析、案例材料、参考答案（若有）。输出建议 `tags`（1～8 个）、可选 `difficulty` 建议、可选一句话 `exam_point_note`（可不落库，仅展示）。
- **AI-TAG-04 P1b**：AI 结果写回前须可预览；确认后写入 `questions.tags`（及可选更新 `difficulty`），并更新 `tags_edited_at`。
- **AI-TAG-05 P1b**：**人工编辑优先**：批量任务默认跳过 `tags_edited_at IS NOT NULL` 的题目；须显式「强制覆盖」才改写并刷新该戳。
- **AI-TAG-06 P1b**：导入 CSV/试卷后可提示「建议使用 AI 补全考点」，不强制自动全量调用（避免突然高额费用）。
- **AI-TAG-07 P1b**：客观案例组内多小题可分别打标；材料文本可作为各小题分析的共享上下文。

### 6.4 AI-GRADE — 主观简答 AI 辅助评分（P2）

- **AI-GRADE-01 P2**：仅考试模式 `short_answer` 参与 AI 评分；客观题（含客观案例小题）不受影响。
- **AI-GRADE-02 P2**：交卷后客观题得分立即可见；含主观简答时，对应小题 `grading_status = pending`（「AI 评分中」），不阻塞客观分与正式简答分（模糊匹配 `earned`）展示。
- **AI-GRADE-03 P2**：AI 根据案例材料（若有）、题干、`reference_answer`、用户作答、小题满分，返回**建议得分**、是否达到及格口径（建议分 ≥ 满分 × 60% 视为「基本掌握」，可配置）、评语、采分点命中列表。
- **AI-GRADE-04 P2**：结果回写后结果页展示「AI 辅助评分，仅供参考」及参考答案；**正式 `earned` / 会话 `score` 不被 AI 覆盖**（双轨，见 ADR-0001）；用户可刷新查看建议分。
- **AI-GRADE-05 P2**：评分失败时该小题标记 `failed`，正式分仍保留交卷时模糊匹配的 `earned`；须提示可重试。
- **AI-GRADE-06 P2**：`short_answer` **不计入错题本**的既有规则保持不变。
- **AI-GRADE-07 P2**：练习模式不提供主观简答作答与 AI 评分入口。
- **AI-GRADE-08 P2**：个人统计、正确率、会话总分一律以正式 `earned` 为准；`ai_score` 不参与累计统计。

## 7. 核心用户流程

### 7.1 会后智能分析（P0）

1. 用户完成刷题或考试，进入结果页。
2. 前端加载当次作答明细，联表查询题目 `tags`（不依赖练习快照是否含 tags）。
3. 前端或 Edge 计算本地考点聚合并展示。
4. 用户点击「生成智能分析」（或首次自动触发一次，产品默认：**首次进入结果页自动触发一次**，失败不阻断页面）。
5. Edge Function 校验归属与配额 → 组装错题/考点摘要 → 调用 DeepSeek → 写入 `session_ai_reports`。
6. 结果页展示总结、薄弱点与建议；可「重新生成」。

### 7.2 揭晓后单题 AI 点评（P1a）

1. 用户在刷题中提交答案或「暂不会」，或进入已完成练习 / 已交卷考试的逐题复盘。
2. 该题已揭晓后，点击「AI 点评」（揭晓前无入口）。
3. 前端调用 `ai-proxy` `explain_question`，携带 `question_id` 以及练习或考试的 `session_id` / `session_type`。
4. Edge 校验 JWT、题目可见性、会话归属与揭晓状态 → 命中缓存则直接返回；否则调 DeepSeek → 写入 `question_ai_explains` → 计 analyze 次。
5. 展示 `exam_points`、`intent`、`pitfalls`、`commentary`；`related_tags` 只读展示。可附一句本地对错 / 跳过说明。不写回 tags，不改分。

### 7.3 题目考点打标（P1b）

1. 上传者进入题库管理，选择单题或批量。
2. 触发 AI 分析 → 预览建议 tags → 确认写入。
3. 之后学习者的会后分析可消费更完整的 tags。点评路径**不**承担写回。

### 7.4 主观简答异步评分（P2）

1. 用户在考试中作答 `short_answer` 并交卷。
2. `finish_exam_session` 完成客观题判分；简答题写入 `grading_status = pending`（及必要时保留模糊匹配兜底分）。
3. 前端或交卷成功回调触发 `ai-proxy` `grade_short_answer`（可按题并行，受限流约束）。
4. Edge 调 DeepSeek → 回写该题 `ai_score` / `ai_feedback` / `grading_status = done`。
5. 结果页轮询或手动刷新，展示辅助评分与评语。

## 8. 业务规则

- **AI-RULE-01 P0**：客观题对错与得分一律以现有精确匹配 / RPC 为准，AI 不得修改。
- **AI-RULE-02 P0**：每用户每日 AI 调用次数设上限（默认：分析类合计 30 次/日，含 `analyze_session` / `analyze_question` / `explain_question`；评分类 50 小题/日；可配置）。超限返回明确错误文案。**仅在成功调用 DeepSeek 并得到可用结构化结果后计次**；上游失败、超时、`ai_disabled`、命中已存 `ready` 报告或题目点评缓存（未 `force`）均不计次。
- **AI-RULE-03 P0**：同一 `session_id` + 类型的成功报告默认复用；「重新生成」成功覆盖后计次一次。
- **AI-RULE-04 P0**：送往 DeepSeek 的内容仅限完成分析/评分/点评所需字段，禁止附带无关 PII（如邮箱）；用户作答文本因评分需要可出站。点评默认**不**发送用户作答（见设计文档）。
- **AI-RULE-05 P0**：产品须在智能分析区固定披露：题干、解析、作答可能发送至第三方模型服务（DeepSeek）进行处理。P1a 点评面板同样披露（题干/选项/解析/参考答案）。完整隐私政策可另跟主需求 NFR，不阻塞本模块 P0。
- **AI-RULE-06 P1b**：批量打标须可中止；已确认写入才改库。
- **AI-RULE-07 P2**：AI 评分展示必须带「仅供参考」标识。
- **AI-RULE-08 P2**：未评分完成的主观题：个人统计与正确率计算遵循主需求「避免把未评分主观题计为错误」；统计口径以正式 `earned` 为准。
- **AI-RULE-09 P0**：无 `DEEPSEEK_API_KEY` 或总开关关闭时，所有 AI action 失败并降级为仅本地能力（会话页）或隐藏打标/评分/点评入口。
- **AI-RULE-10 P0**：`tags_edited_at` 表示「标签已经过上传者确认」（手改或 AI 预览确认）；批量 AI 默认尊重该戳。
- **AI-RULE-11 P1a**：AI 点评仅揭晓后可用；服务端以会话作答记录为准，不以客户端开关为准。
- **AI-RULE-12 P1a**：点评不得修改 `attempt_answers` / `exam_sessions.result_items` 中的 `is_correct`、`earned` 及会话总分。
- **AI-RULE-13 P1a**：`explain_question` 返回的 `related_tags` 默认不写回 `questions.tags`，亦不更新 `tags_edited_at`。
- **AI-RULE-14 P1a**：点评对全部可作答题型开放；与会后报告、上传者打标、简答评分入口分离。

## 9. 数据对象（产品视角）

### 9.1 会话 AI 报告 `session_ai_reports`

| 字段（逻辑） | 说明 |
|--------------|------|
| 所属用户 | 报告所有者 |
| 会话类型 | `practice` / `exam` |
| 会话 ID | 对应 `attempt_sessions.id` 或 `exam_sessions.id` |
| 本地薄弱聚合 | 考点 → 正确/错误/正确率 |
| 总结 / 建议 | AI 生成文本结构化结果 |
| 状态 | `ready` / `failed` |
| 创建/更新时间 | 用于展示与覆盖 |

### 9.2 主观评分扩展（考试结果项）

在考试 `result_items` 元素上扩展逻辑字段：

| 字段（逻辑） | 说明 |
|--------------|------|
| `grading_status` | `scored`（客观题/无需 AI）/ `pending` / `done`（AI 建议分已写入）/ `failed` |
| `ai_score` | AI 建议得分（旁注，不覆盖 `earned`） |
| `ai_feedback` | 评语与采分点说明 |
| `reference_shown` | 是否已展示参考答案（沿用交卷后可见） |

### 9.3 题目考点

继续使用 `questions.tags`；增加可选时间戳 `tags_edited_at`（可空）。不新增必填产品字段。可选展示 AI 建议的难度，确认后写 `difficulty`。

### 9.4 单题 AI 点评缓存 `question_ai_explains`

按**题目内容**缓存教学向点评（不含用户作答），供有权且已揭晓的学习者复用。

| 字段（逻辑） | 说明 |
|--------------|------|
| 题目 ID | `questions.id` |
| 内容指纹 | 题干 / 选项 / 答案 / 解析 / 材料等的哈希；题目改写后视为未命中 |
| 考点 / 考查意图 / 易混点 / 点评 | AI 结构化教学结果 |
| 建议标签 | `related_tags`，仅展示 |
| 状态 | `ready` / `failed` |
| 模型与时间 | 用于覆盖与展示 |

## 10. 非功能需求

- **AI-NFR-01 P0**：会后分析接口在正常网络下，P95 等待用户可感知完成时间目标 ≤ 30s；超时须可失败提示并保留本地聚合。
- **AI-NFR-02 P2**：单题简答评分 P95 ≤ 30s；整卷多题采用异步，不阻塞交卷响应。
- **AI-NFR-03 P0**：密钥仅存 Supabase Secrets；审计上避免在客户端日志打印完整 Prompt/作答长文（开发环境可简化）。
- **AI-NFR-04 P0**：成本可控：限额 + 幂等复用报告 + 批量上限。
- **AI-NFR-05 P0**：AI 失败时核心刷题/考试主路径仍可用。
- **AI-NFR-06 P1b**：打标与分析接口返回结构化错误码，便于前端提示。
- **AI-NFR-07 P1a**：单题点评在正常网络下 P95 可感知完成 ≤ 30s；缓存命中应接近即时；超时/失败不得阻断刷题。

## 11. 验收标准

### 11.1 P0 — 手改 tags + 会后分析

- [ ] 上传者可在题库管理中手改单题 tags 并保存；保存后 `tags_edited_at` 非空。
- [ ] 试卷 JSON 导入：源数据含 tags 时写入题目，不再一律空数组。
- [ ] 完成一次刷题后，结果页可见本地考点聚合（含「未标注」）；已手改 tags 的题出现在对应考点下。
- [ ] 智能分析区有 DeepSeek 第三方处理固定披露文案。
- [ ] 配置有效 DeepSeek Key 时，可生成并展示总结与建议；刷新后仍可看到已存报告。
- [ ] 重复进入同一会话结果页不重复计费（未点「重新生成」）；上游失败不计次。
- [ ] 无 Key / 接口失败时，本地聚合仍可见，智能解读有明确失败提示。
- [ ] 用户 A 无法通过 API 读取用户 B 的报告。
- [ ] 客观题对错与改造前一致，无回归。

### 11.2 P1a — 揭晓后单题 AI 点评

- [ ] 刷题揭晓前无「AI 点评」按钮；提交或「暂不会」后出现且可点。
- [ ] 练习结果页逐题复盘、考试交卷后逐题复盘可点评；考试交卷前无入口。
- [ ] 客观单选/多选/判断、案例小题、以及已展示的简答均可请求点评（有对应 UI 的入口）。
- [ ] 返回考点、考查意图、易混点与点评正文；可展示建议标签但题库 `tags` / `tags_edited_at` 不变。
- [ ] 本题 `is_correct` / `earned` / 会话总分与点评前一致。
- [ ] 同一题内容未变时再次请求不重复计费（未点「重新生成」）；上游失败不计次。
- [ ] 无 Key / 失败时原解析与对错仍可见，点评有明确失败提示。
- [ ] 未揭晓或非本人会话的 API 请求被拒绝；无权见题返回 403。
- [ ] 点评区有 DeepSeek 第三方处理披露。

### 11.3 P1b — 考点打标

- [ ] 上传者可对单题预览并确认写入 tags。
- [ ] 批量任务有成功/失败反馈；强制覆盖与跳过已编辑策略符合 AI-TAG-05。
- [ ] learner 无法对他人题库打标。
- [ ] 打标后的 tags 出现在后续会后分析的本地聚合中。

### 11.4 P2 — 简答 AI 评分

- [ ] 交卷后客观分与简答正式分（模糊匹配）立即可见；简答题另显示「AI 评分中」。
- [ ] 评分完成后展示建议分、评语与「仅供参考」；会话总分未因 AI 改变。
- [ ] 客观案例小题得分仍为精确匹配，与 AI 无关。
- [ ] 评分失败可提示并重试；正式 `earned` 保留；简答仍不进错题本。
- [ ] 练习模式无简答 AI 评分入口。

## 12. 分期与依赖

```text
P0 手改 tags + 会后薄弱点分析
  ├─ 依赖：已完成会话、题库管理可写 tags、题目 tags 可读（允许仍有未标注）
  └─ 不依赖：P1a 点评、P1b AI 打标、P2 评分
  └─ 状态：当前已上线切片

P1a 学习者单题 AI 点评（揭晓后）
  ├─ 依赖：P0 代理 / 配额 / DeepSeek；刷题揭晓与结果复盘播放器
  ├─ 不依赖：P1b tags 写回、P2 评分
  └─ 建议：作为 P0 live 之后的下一切片（先于上传者打标）

P1b 题目考点 AI 打标（原 P1）
  ├─ 依赖：题库管理权限、DeepSeek 代理、P0 手改能力（人工优先策略）
  └─ 提升：P0 分析质量与打标效率；与 P1a 点评写回策略分离

P2 主观简答异步 AI 评分（双轨）
  ├─ 依赖：考试 short_answer、finish_exam_session 扩展点
  └─ 独立：可晚于 P1a / P1b 上线；不改写正式 earned
```

建议上线顺序：P0（已交付）→ **P1a 学习者点评** → P1b 提高题库标签质量 → 最后 P2 处理异步与信度风险。

## 13. 已决事项与开放问题

### 13.1 已决

| 事项 | 决定 |
|------|------|
| 客观案例是否 AI 判分 | 否，精确匹配 |
| 案例题 AI 评分含义 | 仅 `short_answer` |
| 考点存储 | `questions.tags` |
| 代理形态 | 单一 `ai-proxy` + `action` |
| 默认模型 | `deepseek-chat`（可配置） |
| 会后分析 tags 来源 | 联表 `questions`，不强制改历史练习快照 |
| 简答评分时机 | 异步；交卷不阻塞 |
| 练习模式简答 | P0/P1a/P1b/P2 均不做练习简答 UI；简答点评仅在已揭晓入口（如考试复盘） |
| 结果页首次分析 | 自动触发一次 |
| P0 含手改 tags | 是（题库管理单题编辑，不经 AI） |
| 简答 AI 与正式分 | 双轨；AI 不覆盖 `earned`/总分（ADR-0001） |
| `grading_status` | `scored` / `pending` / `done` / `failed` |
| 配额计次 | 仅 DeepSeek 成功返回可用结果后计次 |
| 已确认 tags 判定 | `questions.tags_edited_at`（手改与 AI 确认写入均更新） |
| 试卷 JSON tags | P0 按源数据写入，不再写死 `[]` |
| 第三方披露 | P0 智能分析区固定脚注；P1a 点评面板同样披露 |
| AI 点评可用时机 | **仅揭晓后**（刷题提交/跳过之后，或考试已交卷复盘） |
| AI 点评题型 | 全部可作答题型（客观单选/多选/判断、案例小题、已展示的简答） |
| AI 点评与得分 | 不改写 `is_correct` / `earned` / 会话总分 |
| 点评 vs 打标 | 点评返回教学正文；`related_tags` **默认不写回**；写回仅 P1b |
| P1 拆分 | P1a = 学习者点评；P1b = 上传者 `analyze_question` 打标 |

### 13.2 开放问题（不阻塞 P0）

- 是否向终端用户展示「本次分析消耗 1 次配额」的明细（建议 P1 再做简单提示）。
- 跨会话「薄弱知识点」仪表盘是否并入本模块或留在主需求 §12.2 统计页（建议另页实现，本模块 P0 仅当次会话）。
- 完整隐私政策页面（主需求 NFR）；本模块 P0 仅结果页分析区披露即可。

## 14. 与主需求书的关系修订说明

- 主需求 §2.4「AI 自动出题、AI 主观题评分和在线监考」拆解为：出题与监考仍不包含；**主观题 AI 辅助评分**由本文档 P2 定义。
- 主需求 §12.2 知识点统计：本模块 P0 提供当次会话级消费；全站累计统计仍可按主需求后续实现。
- 主需求 V1.2「AI 辅助出题或解析」：出题仍不做；「解析」包含会后分析、**揭晓后单题 AI 点评**与简答评语。仍**不是**通用聊天助教，且不得在揭晓前提供解析。
